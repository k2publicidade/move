O bootstrap limpa os dados financeiros de demonstração somente no ledger isolado, conservando usuários/regras iniciais. Preparação de fixture e contagem final de idempotência usam `readDb/writeDb`; cadastro, checkout, confirmação, bônus, crédito, saque e leituras de validação passam por HTTP real do Express. Apenas o provedor externo é simulado.

## Regras e limites de interpretação

- O plano de R$55 **não gera automaticamente bônus, diário ou Unilevel**. A compra do plano não é base de comissão. Isso não significa que um associado ativo não possa ganhar por indicação: o fluxo existente concede direto/Unilevel sobre eventos de cotas/diário dos indicados, respeitando o teto de R$500. O teste confirma essa distinção, sem eliminar a elegibilidade existente.
- Cotista conserva teto **total de 250%**, incluindo os 100% investidos; a capacidade adicional de ganhos implementada é **150%**. Para R$65, total 16250 centavos e capacidade de ganhos 9750. O teste não altera esses percentuais.
- 1% e 10% de diário são taxas escolhidas para os runs controlados via API; não são promessa de taxa diária fixa ou rendimento real. Unilevel usa os percentuais da regra ativa retornada pela API, com arredondamento para baixo em centavos.
- Não foi encontrado contrato HTTP de **pontos** nem fórmula definida de conversão para pontos. Foram validadas as métricas reais já existentes (rede/cota/bônus/capacidade), sem inventar pontuação. Uma fórmula comercial futura requer especificação e novos testes.
- O cenário com indicação antes/depois da promoção e os seis níveis adicionais existem exclusivamente no ledger temporário. Ajustes administrativos de Cota/Rede no passo 11 criam saldo suficiente para validar as regras específicas de cada carteira: carência somente Cota e saque Rede com pacote ativo/saldo/mínimo; não são ganhos comerciais reais.
- Se a implementação de alias estiver pendente, o passo 03 permanece vermelho, mas cria um filho por código canônico para permitir investigar os passos financeiros subsequentes. O fallback nunca faz o teste de alias passar.
- O teste não valida DOM, botões/link renderizado, navegador real, implantação, PostgreSQL, infraestrutura do provedor, cron noturno ou pagamento/liquidação real. Confirma HTTP funcional no processo local; diário é processado pelo endpoint MASTER em datas fixas de teste, não pelo cron.
- A confirmação final de payout, a expiração de pacotes, o limite semanal de Cota após maturação, o esgotamento efetivo dos tetos e o upgrade obrigatório após R$500 não são exercitados neste harness. Preservação dos números de teto é validada; preservação de todas as transições exige as demais suítes.

## Arquivos e escopo

A entrega modifica API TypeScript/Express e frontend React, com testes de regressão `reportFinancialBackend` e `reportFrontend*`, além deste harness. Corrige direto automático, Unilevel na Rede, classificação de excesso do associado como bloqueio para upgrade, binding UUID do estorno e links por login com prevenção de ambiguidades. Dashboard separa direto/Unilevel/Diário, desconta estornos da categoria original e apresenta rede, carteiras e disponibilidade efetiva. Pontos permanecem não definidos por falta de fórmula comercial.

Backend PHP legado em `public/api/index.php` não foi atualizado; homologação PostgreSQL/cron/gateway real não foi feita. A consulta pública somente leitura de health respondeu `GoMove API`, mas não comprova versão implantada. Não houve alterações em contas reais. Autenticação GitHub e publicação permanecem pendentes. O mínimo existente de cota R$60 foi preservado; a exigência de elegibilidade a partir de R$65 não determina exclusão de R$60.
